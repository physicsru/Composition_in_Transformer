## 3. 评估

- 每 10k updates（另加 1k / 2k / 5k）：全 10k 原子、1,000 道未见关系对 d2 验证、1,000 道 d2 训练行拟合、监测集（每格前 100 题 × 24 格），都用该臂自己的协议；H 另记同权重强制 R = d 的监测读数。
- 最终（1M）：全 120,000 题按主协议；同一权重的诊断——强制 R = d（全量）、所有深度共用的固定预算网格 R ∈ {1, 2, 4, …, 256}（每格前 500 题）、论文 §6.3 的 KL < 0.01 且熵 < 3.0 停止规则（每格前 500 题）、H 的采样停止；原子与 val_d2 的固定预算读数。
- H 的主指标 = **主动 STOP 且答对**；另报 timeout、错误停止、平均与分位循环数。D 的 R = d 不算学会停止。

## 4. 接入前检查（`python scripts/test_loop_gpt.py`，CPU，全部通过）

1. 每轮复用同一组 4 个 block；LM head 就是 embedding 矩阵本身（同一 storage，两处使用都回传梯度）。
2. 因果 NoPE：同一 `[x, r1]` 后接不同 r2，5 轮后 x、r1 位置的 hidden state 完全相同，末位不同。
3. 右 padding 不改变最后有效位置的读出；129 token 的 d = 128 输入完整处理，改最后一个关系输出即变；模型接口只接收 token。
4. w2 拆出的两个原子查询批量前向 = 各自单独前向。
5. 初始时 `F_θ` 为恒等（残差输出投影为零）但每个 block 都有梯度；stop head 只在 H 有梯度。
6. D 的 loss = 原子行第 1 轮、d2 行第 2 轮的手工计算；H 的终止分布在展开轮上和为 1（剩余质量在末轮），λ 项 = λ · E[T]。
7. H 的逐样本停止推理（active set 逐轮收缩）与逐题参考实现的停止轮、该轮答案、timeout 完全一致。
8. 三个臂同 seed 的骨干初始化 hash 相同；D / P 的 stop head 不进入 AdamW state；三个臂 8 updates 直跑 = 4 + resume 4（权重、AdamW 动量、来源流、R 流、计数器）。
9. 完整 run 写出 `final_eval.json`（主协议、强制 R = d、固定网格、KL / 熵规则、H 的采样停止）。

## 6. 中期观察（09-19 19:00，D 跑到 35 万 updates）与追加的伙伴数对照

- D 的三个 seed：原子 0.998–1.000、d2 训练行拟合 0.998–1.000，未见关系对的 d2 从 1 万到 30 万 updates 一直在 0.003–0.009（chance 0.002），没有上升趋势；d ≥ 3 为 0。D 每个 update 4.5 ms。
- **模型在未见关系对上输出的是什么**（3,000 道未见对 d2，R = 2，35 万 updates 的检查点）：

| 输出 | seed 1 | seed 7 | seed 123 |
|---|---|---|---|
| `r2(x)`——把最后一个关系直接作用在**起点**上，跳过第一跳 | 0.466 | 0.904 | 0.732 |
| 其它实体 | 0.359 | 0.038 | 0.136 |
| `r1` 后接它**训练时的**后继关系（无视真实 r2） | 0.118 | 0.006 | 0.063 |
| 桥实体 `r1(x)` | 0.035 | 0.042 | 0.055 |
| 训练时的前驱关系后接 r2（无视真实 r1） | 0.015 | 0.006 | 0.009 |
| 正确 | 0.007 | 0.004 | 0.005 |

  也就是说原子技能不但学会了、还被用上了：遇到没见过的关系对，模型退回到"对起点做一次原子查询"。它没学到的是"把 r2 作用在**桥实体**上"。训练对 100% 拟合靠的是按 `(x, r1, r2)` 记答案：k = 1 的关系图里每个关系只有一个训练后继，一条 d2 训练行由 `(x, r1)` 就唯一确定，10,000 行各被呈现 6,400 次，没有任何压力让计算经过桥实体。
- 这与本项目已有的证据一致：同一份 k = 1 数据上，只要中间实体是显式输出（第三批的 B / C 协议），未见对 d2 就是 1.0；N0 / P1 里决定"第二跳能否用在陌生上下文的桥上"的变量正是伙伴数（k1 0.19–0.57 → k4 ≥ 0.998）。另外与论文的差别：论文 §6 的两跳训练覆盖全部 100 个关系对（15,000 / 20,000 个 `(x, r1, r2)`），测的是未见**实例**与更深的链；我们测的是未见**关系对**，且只给了 400 对里的 20 对。
- **追加的对照（我加的，标注为方案外）**：同一个 D 臂换到 k = 2 / 4 / 8 的关系图（40 / 80 / 160 个训练对；同一世界、同一 atomic 与 w2 行；数据是第三批已生成的 `chain_chainC_k2` / `chain_chainC` / `chain_chainC_k8`，测试到 d = 32）。run：`halt_Dk2_s1`、`halt_Dk4_s{1,7,123}`、`halt_Dk8_s{1,7,123}`，作业 3397595–3397601（go39，3 h）。若未见对 d2 随 k 上升，说明卡住的是 k = 1 的捷径而不是骨干；之后 D 对 H 的比较应在 k ≥ 4 上做才有区分力。

### 6.1 伙伴数对照的中期读数（09-19 19:35，58 万 updates；最终数待补）

| D 臂，关系图 | 训练关系对 | 未见关系对 d2（验证 1,000 题），10k → 100k → 300k → 500k updates | d3（监测，R = 3） |
|---|---|---|---|
| k = 1（主臂，87 万步） | 20 / 400 | 0.004 → 0.007 → 0.003 → 0.006（chance 0.002） | 0.00 |

同一个骨干、同一个 D 协议、同一批原子与 w2 行，只把每个关系的训练后继从 1 个加到 4 / 8 个，未见关系对的 d2 就在**最初 1 万步内**到 0.91–0.98；k = 1 到 87 万步仍是 chance。卡住未见对 d2 的是 k = 1 的捷径，不是骨干或只监督最终答案。两个后续现象：(i) k = 4 的未见对准确率在继续训练中从 0.94 回落到 0.6–0.8（k = 8 回落较少）——训练行被反复呈现后，记忆解逐步侵蚀组合解，方向与 grokking 相反；(ii) 所有 k 的 d3 都是 0：只训练到两跳时不外推到更深，这与论文 Appendix J 的结论一致。论文侧的对应事实见 [paper_2604.07822_loop_think_generalize_summary.md](paper_2604.07822_loop_think_generalize_summary.md)：论文两个实验都不留出关系对（§5 训练两跳覆盖 39,954 / 40,000 个关系对、每个 `(h, r1)` 平均接 7.2 个不同 r2；§6 覆盖 100 / 100），深度外推靠课程训练见过 ≥ 4 跳。

### 6.2 深度方向的诊断与方向调整（09-19 20:20）

用户确认的目标：只用原子技能、w2、d2 这类容易拿到的浅层数据（行数 O(n²) 以内），k 要放大，泛化到任意深度。

**k = 8 的 D 模型在 d3 上输出什么**（3,000 条相邻关系对全部训练过的 d3 链 `[x, r1, r2, r3]`，82 万 updates 的检查点）：

| 读数 | seed 1 | seed 7 | seed 123 |
|---|---|---|---|
| R = 3 时输出 `r3(r1(x))`（跳过中间一跳） | 0.78 | 0.95 | 0.61 |
| R = 3 时输出非实体 token | 0.20 | 0.00 | 0.36 |
| R = 3 时正确 | 0.00 | 0.00 | 0.00 |
| R = 2 时输出 `r3(r1(x))` | 0.99 | 0.99 | 0.99 |
| 3 轮后在 **r2 位置**能解码出 `r2(r1(x))` | 0.73 | 0.95 | 0.53 |

正确的中间结果其实已经算出来了：因果模型里 r2 位置的状态就是一道 d2 题的终态，`r2(r1(x))` 在那里可解码。失败在于**最后一个位置去 r1 位置取桥实体，而不是去前一个位置取**。训练深度 ≤ 2 时"前一个位置"和"第 1 个位置"是同一个位置，数据无法区分这两条规则；NoPE 又没有直接表达"前一个 token"的手段，模型选了按绝对位置的那条。这与第三批 CoT 模型"先用 r1、再用最后一个关系"的按位置规则是同一种不可辨识性，也与论文 Appendix J（只学到 2 跳不外推）一致。

**调整：**

- k = 1 上的 P1–P3、H2、H3、H1（已开跑）与 C1–C3（排队）全部撤掉：D 在 k = 1 上过不了 d2，它们没有区分力；go39 只剩约 61 node-hours。
- H / Hc / P 改到 k = 8（`data/chain_loop_k8`：160 / 400 个训练对，train / val 与 `chain_chainC_k8` 相同，测试到 d = 128）：H81–H83（go39，3398258–3398260）、C81–C83 与 P81–P83（gj26，3398261–3398266）。
- **相对位置变体（我加的）**：D 臂在 k = 8 上把 NoPE 换成 RoPE（base 100，无新增参数，初始化与 NoPE 逐位相同）：R81–R83（go39，3398255–3398257）。相对位置下"读前一个 token"是同时解释两跳训练数据的最简单规则，并且天然适用于第 3、4、… 个位置。若它在 d3+ 上出现信号，说明深度方向卡在寻址的归纳偏置上；若仍是 `r3(r1(x))`，再考虑把程序放到序列的不同绝对位置（用 w2 式拼接，语义深度仍 ≤ 2）等做法。
