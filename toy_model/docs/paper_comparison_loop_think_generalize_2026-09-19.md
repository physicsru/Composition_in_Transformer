# 当前4-slot latent模型与《Loop, Think, & Generalize》v2的比较

日期：2026-09-19。本文比较用户提供的21页PDF `papers/loop_think_generalize_2604.07822v2.pdf`、作者当前公开代码，以及已经审计的第四/第五批模型。本次更新方法文档及原子来源数据，尚未实现新训练器或启动实验。

后续要求更新：用户已明确下一版加入独立原子数据，与w2/d2联合训练。见[原子联合训练增补](experiments_atomic_joint_next_2026-09-19.md)。以下“没有独立d1训练行”等描述仍指已经完成的第五批历史实验。

最新方法决定：用户进一步要求与论文方法一致；下一版采用全序列共享causal循环，不再以4个独立latent槽为主模型。具体见[论文方法对齐规范](experiments_paper_aligned_loop_2026-09-19.md)。本文表格仍比较已经完成的第五批历史模型。

## 1. 直接回答：我们有几个thinking token？

第五批A–D共享循环模型使用**4个可学习latent槽，每槽256维**。每个样本的内部状态为`Z ∈ R^(4×256)`。初始4槽由参数初始化，之后反复更新同一组槽。T8不是增加到32个独立thinking token，T256也不是生成1024个token。

论文没有另加一组这样的learned thinking槽。按§3.1–4的输入和递归定义，以及公开实现，循环状态是**整个输入序列的hidden states**。例如语义输入`[x,r1,r2]`，这些输入位置的表示一起经过共享Transformer层；实现中的格式token和padding需另按实际数据核对，不能把语义prefix长度当成所有实现的固定张量长度。

## 2. 结构对照

| 项目 | 第五批A–D | 论文v2 |
|---|---|---|
| 循环状态 | 4个全局latent槽 | 输入序列全部位置的hidden states |
| 公式 | `M=Encoder(input); Z_(t+1)=Core(Z_t,M)` | `H_(t+1)=SharedGPT2Stack(H_t; causal_mask)` |
| 输入表示 | 2层双向Encoder只算一次，M之后固定 | 初始token embedding后，每轮继续更新整个序列 |
| 记忆访问 | latent对完整M做cross-attention | 序列内部causal self-attention，无独立固定M |
| 后续关系能否影响r1状态 | 能，r1的Encoder向量已经可包含r2 | 因果mask禁止r1位置看后面的r2 |
| 主要大小 | width256、2heads、2-block core；另有Encoder/Decoder | 默认width768、12heads、4-layer core |
| 输出 | 独立Answer Decoder读取最终Z；生成实体及END | 最后位置hidden state经LayerNorm和tied LM head预测答案实体 |
| 输入/输出embedding | 当前实现分别参数化 | tied weights |
| 位置 | RoPE base100；随机稀疏逻辑槽 | §5两跳用APE；§6深度外推用NoPE |
| 主训练监督 | A只有答案NTP；B/C/D加不同辅助loss | 只监督最终答案位置，无中间实体CoT输出 |
| 循环预算 | 每update从{2,4,8}均匀抽样 | §5固定R=1/2/4/8；§6另比较截断Poisson动态预算 |

来源：论文Figure1/p2，§3.1/p3，§4/p4–5，§5.1/p5，§6.1/p8，AppendixC/p15；本地源码`evidence/miyabi_latent_2026-09-19/toy_model/src/model/latent_executor.py`。

两者都是共享参数的递归计算，也都可在隐空间推理，但第五批不是这篇论文模型的直接复现。

### 为什么因果前缀值得关注

论文中，`r1`位置的状态只依赖前缀`[x,r1]`。对不同后继`r2`，这个位置的输入依赖范围完全一样。原子题`[x,r1]→x1`与组合题的第一跳有天然对应位置。实际是否把该状态学成x1仍由训练决定，不是架构直接提供答案。

我们当前的4个槽都可看完整M，M中的r1也可包含r2。即使读监督令某head指向r1，也没有保证读到的是不依赖伙伴的第一跳表示。这个差异可能使上下文捷径更容易，但**尚未通过匹配对照证明它是失败的唯一原因**。

还需纠正历史范围：**第四批R已经试过共享stack反复更新全序列**，未见d2同样失败（0.34%/0.26%/0.14%）。因此不能把“换成全序列loop”单独包装成必然解决方案。

## 3. 必须分开看论文的两组实验

### 3.1 两跳systematic generalization：§5，p5–7

| 项目 | 论文 | 当前第五批 |
|---|---|---|
| 世界 | 2000实体、200关系，平均出度20 | 500实体、20关系；每个关系是全实体置换 |
| 原子事实 | 40k独立单任务atomic样本 | 10k原子事实放在40k双任务w2行中，每事实8次 |
| 两跳训练 | 273.6k从CID事实构造的两跳题 | 10k；仅20个关系对，每对全部500起点 |
| 训练组合结构 | CID事实上的组合采样；精确关系对覆盖未在PDF列出 | k1有向环：每个r1只有唯一r2 |
| 测试拆分 | 按原子事实95% CID/5% COOD拆分；全部原子事实均单独训练，COOD事实不参加训练组合 | 按有序关系对拆分，测试从没共同训练的关系搭配 |
| 测试数量 | ID 3k；OOD近2k | one_new d2每run/预算5k |
| 输出接口 | 原子与组合均单任务、单实体答案 | 原子事实在双TASK双答案里；组合在单TASK单答案里 |

这两种OOD不是同一个测试。论文要求重组“只在原子形式见过的事实”；我们的主指标要求重组“没见过的关系对”。不能仅比较一个OOD百分比就认定难度或机制一致。

论文两跳样本数/全部原子事实数为273.6k/40k=6.84；相对38k CID事实为7.2。我们是10k/10k=1，并且组合集中在k1图上。覆盖方式与比例都是实质差异；不能只看w2也有40k行就说原子训练相同。

论文仍未通过规模扫描证明某一普适样本复杂度；不能把273.6k直接称为O(n²)，也不能把一个固定比例称为O(n)学习定律。

### 3.2 深度外推：§6，p7–10

此处换为**200实体、10关系的置换世界**：2k原子事实，每深度15k训练题，评估每深度750 held-out题。PDF本身未完全明确两者的去重/包含关系；后续核对[当前公开生成器](https://github.com/OSU-NLP-Group/Loop-Think-Generalize/blob/main/getNhopfact.py)确认其默认先生成15,750个去重程序，再切为15,000训练和750测试。这是对公开生成路径的核实，没有重新生成或核对作者所有发布运行的原始数据。

训练是课程式：

```text
atomic+d2 → d2达到95% → 加入d3
→ d3达到95% → 加入d4 → ……
```

因此最终模型已经看过d3及以上训练题。Figure7/p9的匹配数据实验训练到d12，报告可外推到约d19；Figure5的动态模型课程训练达到d22。这不是仅用w2/d2训练。

**最直接的边界在AppendixJ，p20，Figure19：作者说明，只学到2-hop阶段时，模型还不能外推到更复杂组合；随着课程训练看到更深题，外推比率才上升。** 该图的外推深度使用至少60%准确率定义，也不能与我们的95%强成功门槛混用。

结论：这篇论文支持特定配方下的两跳系统性泛化，以及见过更深训练题之后的有限深度外推；**没有实现用户要求的严格only-w2/d2→d3…任意深度**。

## 4. 为什么我们连未见d2都没过：证据与假说分开

### 4.1 已有直接行为证据：k1伙伴捷径

训练中若r1永远接固定r2，模型可以学习`(x,r1)→最终答案`，无需使用实际第二关系。原始答案分析也发现：未见d2有16%–36.16%的输出与按训练前驱/后继补全的两步答案一致。这是支持伙伴依赖的行为证据，不是已识别某个内部查表电路。

### 4.2 较强候选解释：原子调用接口不同

论文直接训练`[x,r]→f_r(x)`；我们的原子事实是在双TASK、双答案格式下监督。单TASK原子测试只有0.25%–11.55%，而部分run的20行w2新配对测试很高，显示知识在接口改变后不能可靠使用。多数run的低分不是单纯END格式错误，但这仍不能证明参数里没有原子知识。

### 4.3 较强候选解释：缺少独立于后缀的可复用状态

第五批双向记忆与全局槽允许未来关系影响第一跳表示。B/D的第一轮实体读出在新关系伙伴下显著下降，方向上与这个假说一致。论文则提供因果前缀结构，并在AppendixE/p16用activation patching检验r1状态对最终答案的影响；我们的attention hit和固定probe还不足以提供同等因果证据。

### 4.4 尚未匹配的规模、数据量与训练时间

论文默认768维/12头/4层，当前256维/2头/2-block core。论文两跳组合更多，且经历长时间grokking。§5.2报告R4约2k epochs、R2约7k epochs；若epoch为完整遍历313.6k训练行，按PDF batch512条件换算分别约1.226M和4.291M updates。该换算不是已核验训练日志，不能当作精确复制预算。

当前250k updates不等同于论文的训练暴露，但这也不证明单纯延长训练就会成功。尤其k1捷径与接口差异不会因“训练更久”自动消失。

**目前没有证据将失败归因为4个latent槽太少。** 增加槽数是可做的消融，但它不直接消除k1、双任务接口或后缀依赖。当前读出高分/低分也都不足以建立槽数容量下界。

## 5. 接下来最有区分力的比较

1. **建立论文阳性对照。** 用论文全序列causal loop、单任务atomic+d2与对应事实拆分，确认能复现两跳系统性泛化。它是校准对照，不算满足用户严格w2/d2主目标。先记录论文与代码配置差异，避免把未经匹配的缩小版叫作复现。
2. **目标实验保持w2/d2来源。** 在相同世界与10k d2预算下对照k1和多伙伴平衡关系图，并在公共未见关系对上评价。对同一(x,r1)提供多个后继，明确记录起点覆盖与伙伴覆盖的权衡。
3. **结构比较匹配数据与计算记录。** 比较全序列causal loop和4-slot模型；分别检查中间状态对后缀是否不变、原子接口迁移和未见d2。只有d2恢复后，才把d3+结果解释为能否继续执行。

可以先用现有B/D checkpoint固定(x,r1)改变r2做配对诊断，无需新训练。保持纯NTP主线，辅助监督另列，不把辅助成功称为纯NTP涌现。

## 6. 公开代码与PDF之间的复现注意点

2026-09-19读取的作者公开main分支确认：`gpt_utils_systematicity.py`反复更新完整序列，使用tied embedding/head，没有额外learned latent槽。

但`train_systematicity.py`的当前默认值与PDF AppendixC不完全一致：代码batch128、weight_decay0.1，PDF systematic batch512、weight_decay0.01；代码还使用label_smoothing0.1。论文§4描述zero-init，而读取的systematic模型/训练文件未见显式把c_proj置零的步骤。它们可能对应不同运行配置或版本，不能未经日志确认就声称发布默认命令精确复现文中设置。

本次没有执行作者代码，也没有据此判定论文结果错误。这些差异应在复制实验时明确钉住。
