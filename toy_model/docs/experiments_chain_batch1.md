## 2. 三种输出协议（方案 §4）

> | 臂 | d2 目标输出 | 要检验的能力 |
> | A：最终答案 | y END | 现有隐式组合路线在严格数据约束下的基线 |
> | B：实体 CoT | b y END | 离散中间状态能否成为可重复使用的接口 |
> | C：关系＋实体 CoT | x r b s y END | 显式生成当前操作，能否帮助对齐状态与下一关系 |
> ### 4.1 w2 也使用相同的问答边界 …… `Q x r ANS response_1 END Q z s ANS response_2 END` ……只在两段输出上计算损失。
> ### 4.2 …… 1. 只用上述 w2，50k updates。 2. w2 / d2 各 128 行组成 batch256，200k updates。……若混合阶段末五次评估中，三种格式各自三 seed 的平均训练 d2 最终答案准确率均低于 99%，则三种格式统一延长混合阶段到 400k……
> 沿用现有骨干：2 层、d_model=256、2 heads、RoPE base=100、untied embeddings、dropout=0、AdamW lr=3e-4、weight decay=0.1。……增加共用 Q/ANS/END/PAD，max_len=512。
> 建议每个 d2 问题的损失为：CE_final + CE_bridge（若有）+ mean(CE_copy)（若有）+ CE_END。w2 每行是两个子问答损失的均值。
> 相同逻辑数据流按稳定名称分配 RNG……各臂同一步看相同的问题 ID。
> 主要 checkpoint 按 d≤2 验证最终答案准确率选择，平手用验证 loss；同时报告预定尾五点和完整曲线。禁止使用当前覆盖全部测试类型的 best.pt 选择逻辑。

- ✅ `src/data/chain_format.py`：三种协议按原文渲染（已打印核对：A `Q e0 r0 r5 ANS e283 END`；B `… ANS e179 e283 END`；C `… ANS e0 r0 e179 r5 e283 END`）；w2 两段问答、普通因果注意力、只在两段输出上有损失。
- ✅ 每 token 权重：final 1、bridge 1、END 1、copy 共 1（C 的 d2 三个 copy 各 1/3），w2 子问答减半；各臂最终答案权重相同；权重与角色保存在张量里，按角色报告 CE（`tf_*` 字段与 `train_log.jsonl`）。
- ✅ `src/train_chain.py`：phase 1 = 50k × 256 w2；phase 2 = 200k × (128 w2 + 128 d2)；loss = Σ行 Σ_t w_t CE_t / 256；流按 (seed, 流名) 固定，三臂同 seed 同一步同一批题；骨干 2L / d256 / 2 头 / RoPE 100 / untied / dropout 0 / AdamW 3e-4 / wd 0.1 / warmup 100；词表 = pad + 500 实体 + 20 关系 + Q / ANS / END（524）；max_len 512。
- ✅ 选择：`best_by_val.pt` 按验证 d2 的**自主 rollout** 最终答案准确率，平手看验证 loss；不用 `best.pt` 逻辑；每 5k 评估、metrics.jsonl 保留完整曲线。
- ✅ 400k 延长规则：预注册，等结果后按 d≤2 条件决定；`--resume` 支持精确续训（优化器、流游标、RNG 都在 `last.pt` 里）。
- 🟡 "报告实际 token 数和算力"：`manifest.json` 记录每类行的 token 数与监督位置数，`train_log.jsonl` 记录累计 token；FLOPs 未单独估算。

## 5. 疑问后续的读数（`scripts/attn_probe.py`，`runs/attn_probe_all.log`；seed 1，每组 300 题）

工具：(1) 第二层每个 head 从答案位置（2）到 [h, r1 位置, 自身] 的注意力权重；(2) 只替换最后一层某个 head 在位置 1 的 K、V 或 K+V 为同 bridge 源（`<h'><T'><r2>`）的值，看输出。与 N0 的整 residual 替换对照。

### 5.1 电路解剖（所有 grok 的模型一致）

| 模型 | 题组 | acc | L1 head0 [h, r1, self] | L1 head1 [h, r1, self] | head1 只换 V | head1 只换 K |
| --- | --- | ---: | --- | --- | ---: | ---: |
| X_d2（无共现，未 grok） | T→T 未见实例 | 0.12 | [0.33, 0.67, 0.00] | [0.00, 0.01, 0.99] | 0.12 | 0.13 |
| X_w2d2_c40k（固定宽 2） | 同上 | 0.99 | [0.08, 0.08, 0.85] | [0.03, 0.96, 0.00] | 1.00 | 0.99 |
| X_eco_d2 / F_long | 同上 | 1.00 / 0.99 | [0.09, 0.08, 0.83] / [0.04, 0.04, 0.92] | [0.03, 0.97, 0.00] / [0.00, 1.00, 0.00] | 0.99 / 1.00 | 1.00 / 0.99 |
| RC_k4 | H→H 双覆盖（第一跳 H 没训练） | 0.01 | [0.00, 0.07, 0.93] | [0.00, 0.96, 0.04] | **0.99** | 0.01 |
| RC_k8 | H→H 输入覆盖 / bridge 未覆盖 | 0.00 | [0.00, 0.08, 0.91] | [0.00, 0.94, 0.05] | **0.84** | 0.00 |
| RC_k1 | H→H 双覆盖 | 0.00 | [0.04, 0.24, 0.72] | [0.13, 0.45, 0.41] | 0.04（K+V 0.19） | 0.00 |

1. grok 后的两层模型有一个固定分工：**第二层 head 1 几乎只看 r1 位置（0.94–1.00），head 0 主要看自身（0.83–0.97）**。head 1 是 bridge 读取头，head 0 负责当前关系。X_d2（无共现、未 grok）里分工颠倒：head 0 看 r1 位置 0.67、head 1 看自身 0.99，而且换掉位置 1 的 K 或 V 都不改变输出——它在看那个位置，但那里没有可读的 bridge（与 N0 "位置 1 整 residual 替换无效"一致）。
2. **同 bridge 源的作用全在 V 路，不在 K 路**：只换 head 1 的 V，H→H 从 0.01 到 0.99（RC_k4）、0.00 到 0.84（RC_k8 未覆盖 bridge）；只换 K 没有任何作用。即路由（往哪看）已经对，缺的是位置 1 的内容（H1 没算出 bridge）。
3. RC_k1 的 head 1 注意力分散（[0.13, 0.45, 0.41]），只换 V 只到 0.04、K+V 0.19：k=1 时读取头本身还没形成标准分工——P1 的伙伴多样性效应在这里也能看到。

### 5.2 干扰（both 臂）不是路由

| 模型 | 题组 | acc | L1 head1 [h, r1, self] | 同 bridge K / V / KV（head 1） |
| --- | --- | ---: | --- | --- |
| RC_k4 / N2_second / N2_second2x | T→H 未覆盖 bridge | 0.59 / 0.72 / 0.72 | [0.00, 0.99, 0.01] / [0.01, 0.99, 0.00] / [0.00, 1.00, 0.00] | 0.59 / 0.52 / 0.52 等（同源，无变化） |
| RC_both4 / N2_both | T→H 未覆盖 bridge | 0.02 / 0.01 | [0.01, 0.99, 0.00] / [0.01, 0.99, 0.00] | 0.02 / 0.02 / 0.02；0.01 / 0.00 / 0.00 |
| RC_both4 / N2_both | H→H 双覆盖 | 0.66 / 0.74 | [0.13, 0.85, 0.02] / [0.35, 0.64, 0.01] | head1 V → 0.89 / 0.92；两头 KV → 0.92 / 0.98；head0 只换 K → **0.33 / 0.38**（下降） |

- both 臂在 T→H 题上的注意力模式与 second 臂**完全相同**（head 1 看 r1 位置 0.99），同 bridge 换源也不改变输出。第一角色监督关掉的不是路由，是读到未覆盖 bridge 之后 H 的应用（第二层的 OV / MLP 一侧）。方案 §1.3 的"表示 / 路由 / 优化"三选一里，路由排除；表示（H 在第二跳对 bridge 内容的映射只在已覆盖事实上成立）与优化（为什么加第一角色行会把它收窄）还分不开。
- both 臂在 H→H 题上 head 0 也开始看 r1 位置（0.60 / 0.52，T→H 题上只有 0.04）：第一跳角色行让 head 0 也参与读 r1 位置；把 head 0 的 K 换成 T 源的反而把 H→H 从 0.66 降到 0.33。这是 both 臂电路偏离标准分工的直接证据，也是 H→H 低于乘积 8–18 pp 的候选来源。

### 5.3 共现为什么加速：读取端，不是映射本身

`scripts/logit_lens.py`：block-0 在 r1 位置的输出经 ln_f + head 解码为 bridge 的比例（弱代理；T 关系即使 patching 证明 bridge 完全可用也只有 0.14–0.36）：

| 模型 | T 在第一跳 | H 在第一跳（已覆盖输入） | H 在第一跳（未覆盖输入） |
| --- | ---: | ---: | ---: |
| RC_none（H 只共现） | 0.29 | 0.05 | 0.07 |
| RC_first4（H 有第一跳监督） | 0.36 | 0.51 | 0.45 |
| RC_k4（H 只有第二跳监督） | 0.14 | 0.01 | 0.01 |

- H 在 F 基础数据里同样共现（宽 1–4 × 8 次），但只共现的 H（RC_none、RC_k4）在 block-0 没有 bridge（0.01–0.07；N0：H→T 0.00 → 注入 T′ bridge 后 1.00）。有第一跳监督的 H（first4）才有（0.45–0.51，且未覆盖输入也有——但行为上未覆盖输入 0.04，head 级读数显示它需要 K 和 V 一起换才恢复到 0.94，只换 V 0.51：未覆盖输入的 bridge 状态即使部分可解码，位置 1 的 key 也不对，读取头分不到注意力 [0.41, 0.57]）。
- 所以闭合的说法是：**关系在 block-0 的"算 bridge"映射来自第一跳组合监督，逐关系、并部分逐事实地学；共现行提供的是读取端的标准电路（head 1 读前一关系位置的 V、block-0 在每个关系位置对前一个实体做局部更新），有它时第一跳监督一到位就能被用上（X_w2d2_c40k 2.4 万步），没有它时模型先建一条把 h、r1 都拉到末位置的电路（X_d2 的 head 分工颠倒），要 78 万步才慢慢换过来。** 只共现不给映射，只映射没有读取端。这对第三批的含义：w2 行提供读取端，d2 行（每关系 4 个伙伴）提供映射；协议 B/C 把 bridge 写成显式 token，等于把"位置 1 的 V"变成模型自己生成的输入，读取端不再依赖内部状态格式。

C 的原始生成（seed 1 @ 145k）：

```
d3 prompt: Q e86 r3 r8 r12 ANS
   gold : e86 r3 e211 r8 e183 r12 e484 END
   model: e86 r3 e211 r12 e356 END        <- 第一步对；第二步复制的是"ANS 前面那个关系"(r12) 而不是下一个 (r8)；
                                             e356 = r12(e211) 是相对自身状态正确的更新；然后按"两步就停"结束
d4 prompt: Q e118 r13 r10 r4 r9 ANS
   model: r10 e271 r4 e452 END             <- 起点都没复制，直接两步
```

C 的错误分解（d3，500 题）：format 0.67、relation_copy 0.33、state_update 0.002；**相对自身上一状态的更新正确率 0.98**。B 的 d3：early_end 1.0，首个状态就错（own-update 0.10——B 没有显式关系，第一步用的关系就已经按位置读错）。

诊断：**状态更新本身是对的、可重复的（给什么关系就算什么），坏的是控制：关系按"相对 ANS / 相对 Q 的位置"读（d=2 时"第二个"和"最后一个"重合，训练数据分不开这两条规则），停止规则是"两步就停"。** 这两条在只有 d ≤ 2 的训练数据里是不可辨识的——方案 §4.1 已经预见到停止规则不保证外推。

### 6.2 据此追加的臂（作业 3375820 chain-D，9 run，完成 09-17 03:42；D seed 1/7 的终点评估在共享节点上 OOM，由 evalD（3381187，`--rollout_batch 250`）重跑完成；`configs/cells_chain.txt`）

方案 §6 的决策表：新 d2 高、长链低 → "优先分析停止、关系读取和状态重复使用；执行外部逐步调用诊断"，且"若错误分解显示关系读取随距离显著恶化，可在最好的输出协议上增加一个 NoPE 对照"。据此：

| 臂 | 设计 | 想回答 |
| --- | --- | --- |
| chainD（协议 D，"队列 CoT"，我加的格式） | 每个状态后重新复制**剩余**的关系列表：`x r1 r2 r3  b1 r2 r3  b2 r3  b3 END`；下一关系永远是当前状态后的第一个 token，剩余列表空则 END | 把"读哪个关系"和"何时停"都变成与 d 无关的局部规则后，d ≤ 2 学到的更新能否重复到 d = 32；d=3 的新点只在"复制一个长度 3 的列表"（长度外推的最简单形式） |
| chainC_nope（C，无位置编码） | 方案 §6.1 的诊断对照（模型新增 `use_rope` 开关） | 关系按位置读的捷径是否依赖 RoPE |
| chainD_nope | D + NoPE | 同上，对 D |

D 的 completion 长度是 O(d²)（d=32 时 562 token），故 `--max_len 1024`。

**追加的对照（作业 3376708 chain-d3，6 run，完成 09-17 05:47；离开严格 w2/d2 约束，标为对照）**：chainC_d3 / chainD_d3 在混合阶段每步用 16 条深 3 训练题（训练图上全部 2 边游走 × 全部起点 = 160k 行）替换 16 条 d2。问的是：既然 d ≤ 2 的数据分不开"下一个"和"最后一个"，**只演示一个更长的深度**（d=3）够不够让位置规则变成序列规则、并外推到 d=32；还是两层模型即使看到规则也不会循环。这些臂里 all_seen|d3 变成训练拟合格，d ≥ 4 与含新邻接的 d3 仍是外推。外部逐步调用诊断（方案 §6.1）已加进最终评估（`stepwise_external`：程序每步喂 `Q s_t r_(t+1) ANS`、自己串接预测实体），对 A/B/C 的最终 checkpoint 用 `--eval_only` 补跑；它衡量原子更新是否可靠，不算自主完成。

读法：

1. **伙伴数、层数、位置编码都不改变 d ≥ 3 = 0。** k=1 到 8、2 层到 4 层、RoPE 到 NoPE，只要训练里只有 d ≤ 2，所有 CoT 协议在 d ≥ 3 上都是 0，首错仍是按位置选关系。NoPE 只是让 d2 的新对泛化变差（C 0.39–0.68），没有去掉位置捷径——捷径不依赖 RoPE，因果 mask 本身就提供位置信息。
2. **只答案的 A 在 4 层同样不泛化到新关系对**（0.005–0.014）：这个严格数据下的隐式路线的失败不是容量问题。
3. **深 3 对照最说明问题**：加入 d3 训练题后，d3 立刻到 1.0，包括含从未训练过的邻接的 one_new / random 链（这不是拟合）；但 d4 仍然是 0。模型把 d=3 也学成了一条独立的位置规则，没有从 {1, 2, 3} 归纳出"对任意长度重复"。方案 §1 的 d∞ 目标在这个模型 + 这些格式下没有出现，无论演示到多深，只覆盖到演示过的深度。
4. 与之对照，外部程序逐步调用同一模型到 d=32 全 1.0（§6.3）：循环控制由程序提供时深度不受限。按方案 §6.1 的说法，下一步是共享权重的 recurrent cell / 固定局部窗口的结构化执行器，并明确"训练学会转移"与"架构提供循环"的区别；或者在训练里覆盖到目标深度（那就不再是浅层训练）。

结论：在只有 d ≤ 2 的训练数据下，协议 C 的两层模型学到了**完全正确、可重复的单步更新**（给它任何关系它都算对）和**完美的 d2 跨关系对泛化**，但控制规则是位置性的："第二个关系 = ANS 前面那个"、"两步就停"。方案第 9 节的首要反证成立：d2 很好、第三步就错、错误集中在读取下一关系与停止。
