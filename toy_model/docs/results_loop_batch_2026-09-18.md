# 第四批结果：局部执行接口 vs 内部循环（设置与数字）

日期：2026-09-18。方案：[experiments_loop_next.md](experiments_loop_next.md)；实现与逐条对照：[experiments_loop_batch1.md](experiments_loop_batch1.md)。本文只做一件事：把每个臂**到底是什么设置**和**得到什么数字**写清楚，让不看代码的人也能判断结论的边界。

## 1. 一句话结论

同样的 40k w2 + 10k d2 浅层数据、同样的 2 层 Transformer：

- 把"一次调用只看（当前实体，当前关系或 EOS）、输出一个动作"作为接口（L），模型在 **1,000–1,200 updates** 内学准全部 10,500 个局部输入，之后 **120,000 条测试链、深度 2–128 无一错**；只用 w2 训练（L-w2）结果逐格相同。
- 让同一接口保留任务内历史（L-history），更新随历史长度单调漂移：d2 0.65–1.0，d3 0.1–0.4，d ≥ 8 为 0。
- 完整序列输入、共享模块循环 T 次（R）：d2 **新关系对** 0.001–0.004（chance），任何 T 都一样；加上 CoT（RC）d2 新对 1.0，d ≥ 3 仍 0，错误与不循环的模型同型。
- 训练好的 CoT 模型由程序逐步调用（O）：到 d128 全部 1.0。

即：瓶颈不在原子更新，而在"谁选下一个关系、谁决定停止"。把这两件事局部化并交给模型学（L）可以；让模型在完整序列或历史里自己找到它们（R、RC、L-history）在这批数据上都没有。

## 3. 各臂的设置

### 3.1 O：外部控制循环（不训练）

- 模型：第三批训练好的 chainC_k1（协议 C，非循环，同样的数据和日程，选点用 val_d2），三个 seed 的 250k 与 best_by_val。
- 自由 rollout：给完整题 `Q <e_x> <r_1> … <r_d> ANS`，模型自己生成 `<e_x> <r_1> <e_b1> <r_2> … <e_y> END`，按完整轨迹计分。
- 外部逐步调用（`stepwise_external`）：程序每步只给一道一步题 `Q <e_s_t> <r_(t+1)> ANS`，解析模型输出的实体作为下一步状态，程序自己数步数、自己停止。模型学不到任何新东西；它只回答"原子更新是否全表可靠"。

### 3.2 L：局部执行器（重置上下文）

每次网络调用是一条独立的短序列，只包含一个局部观察和一个动作：

```
STEP 调用   OBS STATE <e_x> HEAD <r_j> ANS   ->   STEP <e_y> ADVANCE END_CALL      (y = r_j(x))    6 + 4 token
HALT 调用   OBS STATE <e_x> HEAD EOS   ANS   ->   HALT <e_x> END_CALL                              6 + 3 token
```

- **训练数据的编译**（只来自 w2 / d2）：一道 d2 `(x, r, s)` → 三次调用 STEP(x, r)→b、STEP(b, s)→y、HALT(y)；一行 w2 → 两个独立任务，各两次调用 STEP(x_i, r_i)→t_i、HALT(t_i)。训练用正确的中间实体。
- **监督与损失**：每次来源题呈现固定 2 个 STEP + 1 个 HALT 监督调用。d2 只有一个 HALT；w2 有两个，由冻结 RNG（seed 派生）每次呈现均匀选一个计损失，另一个保持可见但无损失。`L_row = 0.5 × mean(L_STEP1, L_STEP2) + 0.5 × L_HALT`，其中每次调用的 loss 是其输出 token 的平均 CE；等价于 STEP 输出 token 权重 1/16、选中 HALT 输出 token 权重 1/6，最后除以 256。观察 / 提示 token 不计损失。
- **每 update 的调用数**：阶段 1（256 w2）1,024 次调用 = 512 STEP 监督 + 256 HALT 监督 + 256 HALT 可见无损失；阶段 2（128 w2 + 128 d2）896 次 = 512 STEP + 256 HALT 监督 + 128 HALT 可见。
- **累计曝光（`exposure.json`）**：每个原子事实恰好 12,800 次 STEP 监督（min = max）；每个实体 127.1k–128.9k 次 HALT 监督、204,800 次可见 HALT；来源题呈现 38.4M w2 + 25.6M d2。
- **运行程序（测试）**：程序保存关系序列、读当前 HEAD、执行 ADVANCE、保存模型返回的实体；每次调用清空上下文（模型只看到那 6 个 token）；只使用模型自己预测的实体；不强制解码；每次最多生成 6 token，合法输出只有上面两种形状，其它一律 `format` 错误；关系处 HALT = `early_halt`（提前停止），EOS 处 STEP = `overrun`（越界），实体错 = `state_update`，HALT 返回别的实体 = `halt_entity`；调用上限 d + 2（从未触及）。一条链正确 = 恰好 d 次合法 STEP 且实体全对，再一次合法 HALT 返回终点。
- **局部表**：每次评估枚举全部 10,000 个 `(x, r)` 和 500 个 `(x, EOS)` 的单次调用 greedy 输出（动作、实体、合法性、原始 token、logit margin）；用表重放测试链（四种组合：模型 / 正确 × 更新 / 控制，缺实体单列为 `missing_update`，不填正确值），并逐题比对真实调用与表重放是否一致。
- max_len 64。

### 3.3 L-w2：同一执行器，只用 w2

与 L 唯一的差别：阶段 2 每 update 用 256 个 w2 来源题替代 128 w2 + 128 d2，因此从头到尾没有任何 d2 题参与训练或选点。每 update 仍是 512 STEP + 256 HALT 监督；累计每事实 12,800 次 STEP 监督（与 L 相同）；HALT 可见 256,000 / 实体（比 L 多，因为 w2 每次呈现有两个 HALT）；来源题呈现 64M w2。

### 3.4 L-history：同一执行器，保留任务内历史

- 观察 / 动作 / 编译 / 损失 / 权重 / 来源题顺序 / HALT 抽签 / 初始化与 L 完全相同（同 seed 下阶段 1 的 loss 曲线逐点相同）。
- 差别只有一个：同一任务的调用拼成一条序列并保留在上下文里。d2 → `[STEP, STEP, HALT]` 三次调用（29 token）；w2 的每个子任务 → `[STEP, HALT]`（19 token），两个子任务之间重置。
- 位置编码：**每次调用的 RoPE 位置从 0 重新开始**（0–9），因果 mask 按真实 token 顺序。所以测试时 d = 128 的记录有 129 次调用、约 1,290 个 token，位置全部落在 0–9 内重复。max_len 4096。
- 测试时记录里放的是模型自己生成的调用（合法 STEP 的 10 个 token），训练时是正确的。
- 单次调用表对它只是诊断（HALT 从未作为记录的第一次调用出现）；主读数是真实调用。

### 3.5 R：完整序列 + 共享模块循环 + 答案级监督

- 输入输出：协议 A。`Q <e_x> <r_1> … <r_d> ANS` → `<e_y> END`；w2 行是一条序列里的两道一步题（各自的答案 + END 计损失，权重减半）。只监督答案与 END，没有中间实体、没有动作。
- 模型：同一个 2 层模块 `B_θ` 对整个序列反复应用 T 次，`h^(t+1) = B_θ(h^(t))`，最后 LayerNorm + 输出头；位置在循环间不变，没有循环编号 embedding；每个 block 的 attention / MLP 输出投影零初始化（模块起始是恒等映射）。自回归生成的每个 token 用同一个 T。
- 训练：每个 update 独立抽 T ∈ {2, 4, 8}（等概率，与题目无关；实际计数每个 seed 三种各约 800–860 次 / 2,500 次记录）。其余与 §2 相同。
- 测试预算（预先规定）：`T(d) = min(128, ≥ max(8, d) 的最小 2 的幂)`，即 d ≤ 8 → 8、16 → 16、32 → 32、64 → 64、128 → 128；另报固定 T = 8；在 50k / 150k / 250k 检查点上算 T ∈ {1, 2, 4, 8, 16, 32, 64, 128} × 全部深度的矩阵（监测集 500 题/格），不用于选点；原子、验证、外部逐步调用用 T = 8。
- 最终矩阵：8 个深度全跑。

### 3.6 RC（方案外补充）：同 R，但输出用协议 C

- 唯一差别：输出是关系 + 实体 CoT，`<e_x> <r_1> <e_b1> <r_2> <e_b2> … <r_d> <e_y> END`（复制 token 合计权重 1，每个中间实体 1，答案 1，END 1）。加它的原因：不循环的协议 A 在这份数据上 d2 新对本来就是 chance，R 若不过 d2 就看不出循环对深度的作用。
- 最终矩阵限 d ≤ 32（T = 128 下 260 token 的自由生成太贵）；矩阵与监测同样只到 d32。

## 4. 结果

### 4.1 O：外部循环到 d128 全对，自由生成 d ≥ 3 全 0

三个 seed × 2 检查点 × 24 格 × 5,000 题（作业 3385035）：

| 读数 | d2 | d3 – d128 |
|---|---|---|
| 外部逐步调用 | 1.0000 | **1.0000**（144 格无一错，含 d64 / d128） |
| 自由 rollout 完整轨迹 | 1.000（三类别） | 0.000 |
| 原子 10,000 项 | 1.0000 | — |

### 4.2 L 与 L-w2：局部表全对，120,000 条链全对，两臂逐格相同

三个 seed × 4 个检查点（250k、245k、240k、best_by_valw2 = L 60k / 230k / 210k，L-w2 20k / 160k / 235k），每一个都是：

| 读数 | L | L-w2 |
|---|---|---|
| 局部表 10,500 项 | 全对；正确项最小 margin 4.8–10.6 | 全对；最小 margin 4.8–12.3 |
| 24 格 × 5,000 题完整轨迹 | **全部 1.000** | **全部 1.000** |
| 真实调用 vs 表重放 | 每格 1.000 一致 | 每格 1.000 一致 |
| 四种重放 | 全 1.000 | 全 1.000 |
| w2 验证 / d2 验证 | 1.00 / 1.000 | 1.00 / 1.000 |

训练过程（作业 3385016 / 3385017）：lr 3e-4 无裁剪，每个 run 有 2–7 个评估点被 loss 尖峰打坏（表准确率 0.002–0.52，全深度归 0，三个 seed 在 10k 都有），下一个评估点即恢复；240k / 245k / 250k 都不在尖峰上。每 run 1.55–1.65 h（三个 run 共用一张 GH200），全矩阵评估 123–149 s。

**涌现时刻**（作业 3385478：同配方前 5k updates 每 200 步评估一次）：

| seed | 表首次 ≥ 0.99 | 表首次全对 | t_d（连续三点 ≥ 0.95，三类别取最小） |
|---|---|---|---|
| 1 | 1,000 | 1,200 | d2–d8：1,000；d16–d128：1,200 |
| 7 | 1,200 | 1,200 | 全部深度 1,200 |
| 123 | 1,200 | 1,200 | 全部深度 1,200 |

seed 1 在 800 / 1,000 / 1,200 updates 的表准确率 0.74 / 0.995 / 1.000 对应 d2 / d8 / d128 完整轨迹 0.54 / 0.09 / 0.00 → 0.98 / 0.96 / 0.52 → 1.00 / 1.00 / 1.00：深链的"陡升"是单步错误率 ε 经 `(1-ε)^d` 放大，全部深度在表全对的同一个 200-update 窗口内一起达标；1,000 updates = 每事实约 25.6 次 STEP 监督。

### 4.3 L-history：更新随记录长度漂移

250k final，全矩阵 120,000 题（作业 3385018；s7 的 245k 与 final 一致，其余检查点补评中）：

| seed | d2 all_seen / one_new / random | d3 | d4 | d8–d128 | own-update，d2 … d128（one_new） |
|---|---|---|---|---|---|
| 1 | 1.000 / 0.999 / 0.999 | 0.10 / 0.09 / 0.09 | ≤ 0.004 | 0 | 1.00 0.70 0.54 0.28 0.14 0.07 0.04 0.02 |
| 7 | 1.000 / 0.646 / 0.652 | 0.40 / 0.22 / 0.12 | ≤ 0.07 | 0 | 0.82 0.69 0.57 0.33 0.17 0.09 0.05 0.03 |
| 123 | 1.000 / 0.787 / 0.797 | 0.31 / 0.20 / 0.14 | ≤ 0.04 | 0 | 0.89 0.70 0.59 0.34 0.18 0.10 0.05 0.03 |

- d3 的首错 78–91% 是 `state_update`（模型自己的实体更新错）；d ≤ 4 全部在正确位置 HALT，停止本身没错；d128 全部 `overrun`（EOS 处仍 STEP）。
- own-update 准确率随记录里已有的调用数单调下降，三个 seed、三类别几乎同一条曲线：同一个局部操作在更长历史下不再复用。
- seed 7 / 123 的 d2 在训练关系对上 1.000、新关系对 0.65 / 0.79：记录里可见的 r1 被用来预测第二步（重置臂不可能有这种依赖；seed 1 没有）。
- 阶段 1（只有 `[STEP, HALT]` 记录）时第二次调用不看 HEAD 一律 HALT 或输出非法；阶段 2 加入 `[STEP, STEP, HALT]` 后 d2 / d3 从 55k 到 235k 基本不变，不是训练不足。
- 训练 7.3–8.6 h；监测评估 500–640 s，全矩阵 5,300–6,450 s（无 KV cache，d128 每题 129 次调用 × 6 次前向）。

### 4.4 R：新关系对 d2 = chance，任何循环预算都一样

三个 seed × 4 个检查点（作业 3385019）：

| 读数 | 结果 |
|---|---|
| 原子（T = 8）/ w2 验证 | 1.000 / 1.00（s7 的 245k 是尖峰点：0.874 / 0.75） |
| all_seen d2（训练边） | 1.00（T(d) = 8）；T = 1 时 0.53–0.92（从未以 T = 1 训练） |

## 5. 结论与边界

1. **能力命题成立，且是"表 + 归纳"意义上的成立。** 在 L 的接口下，任意深度正确等价于 10,500 个局部输入全对（每步保持"当前实体 = 已消费前缀的真实结果"，关系数严格递减，耗尽时 HALT）。三个 seed 的每个报告检查点都全表正确，120,000 条链全对，真实调用与表重放逐题一致。这说明浅层事实学习加一个规范的执行接口足以支持可检验的深组合；**不说明** d2 触发了任何自主递归算法——L-w2 逐格相同，且局部输入里已经没有关系配对信息。
2. **机制命题没有成立。** 完整序列输入的共享循环（R）在答案级监督下连 d2 新关系对都是 chance；加 CoT（RC）只到 d2，d3 起按位置选关系并两步即停，与不循环时一样。这一批没有观察到"共享计算自行产生可迭代状态"。
3. **历史访问本身破坏复用。** 同样的接口保留记录后，更新准确率随记录长度单调下降，且关系对身份从记录渗入更新。训练记录最长只有 3 次调用，所以这不能推广为"所有历史模型都如此"，只说明在本协议下重置是有效的。
4. **不算 planning。** L 的关系序列由程序提供并逐个送到 HEAD；模型只学"如何更新、何时 STEP / HALT"。搜索或选择路径的任务要另定义。
5. 未做：新世界 43 / 44 的确认、E / R scaling、held-out 关系只在 w2 出现的迁移版本（方案 §12 P2）。

- 训练：`python train_local.py --data_dir ../data/chain_loop --save_dir ../runs/loop_L_s1 --seed 1 --max_len 64`（`--w2_only` = L-w2；`--history --max_len 4096` = L-history）；`python train_chain.py --data_dir ../data/chain_loop --save_dir ../runs/loop_R_s1 --seed 1 --protocol A --vocab_ext --loop_T 2,4,8 --zero_init_out --select_by w2 --small_test_depths 2,3,4,8,16,32,64,128 --final_extra_ckpts auto`（RC：`--protocol C --small_test_depths 2,3,4,8,16,32 --final_depths 2,3,4,8,16,32`）。
- 驱动：`scripts/pbs_loop.sh` + `configs/cells_loop.txt`；O：`MODE=O`；补评：`MODE=eval,EVAL_RUNS=…,EVAL_TAGS=…`。运行程序 / 计分的故障注入测试：`python scripts/test_local_runner.py`。
- 作业：3385016 L、3385017 L-w2、3385018 L-history、3385019 R、3385020 RC、3385035 O（3385021 因六个评估共用一卡 OOM 重提）、3385478 early。
- 每个 run 目录 `runs/loop_<cell>_s<seed>/`：`manifest.json`（配置、参数量、词表 hash、数据 hash、每 update 的调用与监督数）、`metrics.jsonl`（每 5k 的全部读数）、`train_log.jsonl`（每 100 步 loss / 每类 CE / T）、`exposure.json`（每事实 / 每实体累计曝光）、`final_eval_{final,ckpt_245000,ckpt_240000,best}.json`（全矩阵、表统计、四种重放、一致性、验证）、`predictions_{final,best}.jsonl`（每条链每次调用的原始 token）、`table_*.json`（10,500 项表）、`loop_matrix_*.json`（R / RC 的深度 × T）、`ckpt_*.pt`、`best_by_valw2.pt`。O 的结果在 `runs/chain_chainC_k1_s*/final_eval_O_{final,best}.json`。
