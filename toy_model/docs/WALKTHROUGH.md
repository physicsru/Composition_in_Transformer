## 1. 问题与设计

### 1.1 来源

LLM 项目（`/work/go39/b20033/code/generalization/doc/PAPER_SUMMARY.md`）的结论：组合泛化 = 可自由迁移的组合过程 × 逐技能的负载下绑定 × 深度执行可靠性；组合侧只需一层多样演示（O(n)），原子侧需要每个技能在多任务上下文里的共现练习（E-co，O(n)），没有一项随组合数量增长。W2D2 最小设定（原子 + 全技能宽 2 共现 + 只在 train 技能上的深 2 组合）在 Qwen3-4B 上 held-out d4/d8 = 0.72/0.13。

toy 的目标：在一个两层小模型上把这三个因子拆开测量并做理论分析。LLM 自带位置不变的技能表示和组合过程，toy 必须从数据里学出这两种不变性，所以 toy 上首先要找到"会组合、会不变"的 regime，然后才能问 held-out 技能的问题。

### 1.2 对应关系

| LLM 实验 | toy | 备注 |
|---|---|---|
| 25 个字符串算子 | R 个关系 `<r_j>` | 稠密世界：每个关系是实体集上的随机置换（全函数，不在复合下封闭）；稀疏世界（`--out_degree k`）：每个实体有 k 个随机关系、尾随机（Wang et al. 几何，部分多对一函数） |
| train / held-out 算子 | R_train / R_heldout | held-out 关系只出现在原子和共现行里，**从不进任何组合** |
| 输入串 | 实体 `<e_i>`，N = 500 | |
| depth-1 原子任务 | `<e_h><r><e_t>` | |
| E-co 共现（1–4 任务/答案） | 宽 k 行 `<e_h1><r1><e_t1><e_h2><r2><e_t2>…` | `--group_size 1 --group_size_max 4 --group_passes 8`：宽度均匀 1–4，每个事实换 8 次伙伴 |
| 深 2 组合（只在 train 算子） | `<e_h><r1><r2><e_t>`，r1, r2 ∈ R_train | 中间实体不输出 |
| RA 格式、召回遗漏、抄写错误 | 不存在 | toy 去掉了格式变量 |

loss 规则：每个"紧跟关系 token 之后的实体 token"都算 loss（`data/dataset.py::answer_positions`），所以宽 k 行有 k 个监督位，链只有最后一位。对原有 functor 数据这与"最后一位"完全一致。

### 1.3 测试类型（每类 300–500 条，`by_type/<type>.json`）

| 类型 | 内容 | 读什么 |

| `d2_train_seen` | 训练里出现过的组合 | 拟合 |

随机水平 1/N = 0.002。

### 2.2 文献核对

- **arXiv:2602.01992 是本仓库自己的论文**（Emergent Analogical Reasoning in Transformers）。它没有组合 grokking：组合准确率紧跟训练准确率，约 100 步饱和。原因是关系是边标签（20 实体、10,000 关系），每个标签只在一条 E1 边及其 E2 镜像上出现，(头实体类别, r2) 唯一决定答案（1440/1440），组合是查表。其步数不能迁移到本设置。有用的两点：1/2/4 层组合都在 ~100 步达 1；wd 0–1、lr 1e-4/1e-3 都不影响组合。
- **Wang et al. 2024（arXiv:2405.15071）是真正的参照**：|E| = 2000、|R| = 200、出度 20、40k 原子全在训练；φ = 组合/原子 ∈ {3.6, 5.4, 7.2, 9.0, 12.6, 18}；8 层 768 维；AdamW lr 1e-4、2000 步 warmup、wd 0.1、batch 512。ID 准确率：φ 3.6 在 3e5 步只有 0.08（不 grok），5.4 → 0.31，7.2 → 0.84 @3e5，9.0 → 0.95 @2e5，12.6 → 1.0 @1e5，18 → 0.99 @2e4；wd 0.3 快近一倍；模型越大越快；**只以原子形式见过的事实，其组合（OOD）在 2M 步内始终为 0**。结论：第一轮 φ = 2、196k 步、小模型、10 倍 lr 不 grok 是 regime 问题，不是 bug。

### 2.3 基础设施发现

- PyYAML 把 `lr: 1e-4` 读成字符串，仓库自带 `default.yaml` 本地直接跑会崩；`train.py` 现在强制转 float。
- 登录节点 torch 默认 144 线程，小模型慢 60 倍；CPU 冒烟必须 `OMP_NUM_THREADS=1`。
- GPU 不是瓶颈：单进程 batch 256 每 epoch 1.9 s，6 进程共享每进程 2.2 s，功耗 150–170 W（空闲 87 W）。瓶颈是每个 epoch 对每条样本重做正则分词与逐条拼 tensor。改为一次性预编码到 GPU 整块 tensor、按索引切 batch（`data_loader: tensor`，评估结果与旧通路逐类型一致）后：

| 单张 GH200，25k 训练行 + 10k 测试行 | 旧通路 | tensor 通路 |
|---|---|---|
| 单进程 batch 256 | 1.90 s/epoch | 0.80 |
| 单进程 batch 1024 | 1.03 | 0.33 |
| 单进程 batch 4096 | 1.20 | 0.23 |
| 6 进程共享 batch 256（每进程） | 2.2 | 1.83 |

  加大 batch 缩短 epoch，但 grokking 按更新步数计；第三轮按 Wang 用 batch 512。评估 batch 修复后无影响。
- `best.pt` 按全部测试类型的 macro CE 选，OOD 类型随训练越来越自信地错，所以它总是早期 checkpoint；分析用 `epochNNNN.pt`。
- PBS：short-g 满时用 regular-g（路由到 small-g）；一次 `Execution server rejected request` 的系统 hold 只能删掉重交；`#PBS -p 1023` 已在脚本里。

### 2.7 深 2 泛化为什么慢：X_d2 的错误类型调查（2026-09-16）

工具：`scripts/error_types.py`（把每条深 2 测试题的 argmax 归到 correct / bridge=r1(h) / r2_only=r2(h) / swap / r1_twice / r2_twice / atomic_of_h / atomic_of_b / train_pair_ans / train_head_ans / other，并给出正确答案、bridge、r2(h) 的概率质量与 top-1 置信度）、`scripts/logit_lens.py`（每层每位置的 residual 经 ln_f+head 解码，看 bridge 在哪里可读）、`scripts/patch_bridge.py --positions 2`。对象：X_d2 s1/s123、X_w2d2 s123、F_long s1（对照，已 grok），均 epoch 1400。

**错误分布（未见实例，X_d2 s1 / s123，acc 0.12 / 0.06）**：r2_only 0.13 / 0.12（跳过第一跳，直接把 r2 用在 h 上；随机水平 0.002）、atomic_of_b 0.23 / 0.24（答案是 bridge 的某个一跳邻居，即 bridge 算对了但第二跳用错关系；随机水平 0.04）、bridge 0.03 / 0.05、r1_twice 0.04 / 0.05；train_pair_ans 0.32 / 0.31 在这个测试类型上没有信息（每个训练 pair 的答案覆盖 70% 实体，和随机一样）。top-1 平均置信度只有 0.41（F_long 0.98），正确答案在 top-5 里 0.30 / 0.19。F_long 在 grok 中途（epoch 200，acc 0.48）的错误里 atomic_of_b 同样是 0.18：**"第二跳用错关系"是组合电路形成过程中的主要中间错误**。X_w2 完全没有结构（other 0.90）。

**机制差异（logit lens + patching）**：三个模型 block-1 在 r1 位置都能以 p ≈ 0.995 解码出 bridge——那是单任务原子监督直接训练出来的（`<e_h><r1>` 的答案位置）。差别在 **block-0**：两层模型里第二层的注意力只能读到各位置 block-0 的输出，所以第二跳要用 bridge，第一跳必须在 block-0 就算完。F_long：block-0 在 r1 位置解码 bridge 0.58，位置 1 patching 跟随率 0.998，位置 2 patching 无效——bridge 在第一层 r1 位置算出，第二层 r2 位置读它。X_d2：block-0 在 r1 位置解码 bridge 0.29，**位置 1 patching 完全无效（同 bridge 换源 0.103、随机源 0.100，与不换 0.123 相同）**，位置 2 patching 有效（同 bridge 换源 0.13 → 0.59，跟随源 0.54，训练过的实例也从 1.0 掉到 0.59）——X_d2 把 h、r1 一起拉到 r2 位置在 block-0 里做部分 bridge、再由 block-1 应用 r2，是一条"全部在末位置"的电路，与单任务行学到的原子电路（当前 token 是关系、注意前一个实体）形状不同，所以不能复用，只能慢慢重新记。X_w2d2：block-0 在 r1 位置解码 bridge 0.69，位置 1 跟随率 0.29——宽 2 行把第一跳往 block-0 推了一些，读取通路只形成了一部分。

12. **（P2，3 seed）** 零 H→H 监督下，H 在两个角色上分别接入（各 4 伙伴、400/500 覆盖）后，两个角色事实都已覆盖的 H→H 达 0.79–0.90（单角色臂 ≤ 0.018，任一角色未覆盖 ≈ 0.02）；两个角色分别可用足以连接。同时第一跳角色对未覆盖输入几乎不迁移（0.02–0.07），与第二跳（第 11 条）不对称；both 臂里第二跳的未覆盖迁移也消失（0.02–0.09），原因待"单角色双剂量"对照。
10. **（P3；N0 已把 seed 1 扩到全部 8 个 H，其余 seed 在跑）** 两层模型的两跳机制：第一层在 r1 位置算出与上下文无关的 bridge 状态（任何 `<x><T>` 前缀，包括单任务行，都给出可被读取的 bridge），第二层在 r2 位置经注意力读它并应用 r2；held-out 关系能否在第二跳应用，取决于 H(b) 这条事实是否以第二跳角色出现过（RC_k4 全 H：已覆盖 bridge 的注入被跟随 0.999，未覆盖 0.61，均匀源 0.92；F_perrel1 0.66–0.70 / 0.30–0.38；零覆盖 0.004），bridge 计算本身对 held-out 题没有问题。

## 4. 预注册读数规则（对正在跑的作业）

5. **规模**：若 2 层 d256 能 grok 但 4 层明显更快，理论分析仍以 2 层为主，4 层作为对照。
