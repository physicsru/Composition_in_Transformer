## 1. 新的训练边界

- 下一版必须包含独立的原子单任务数据，而非仅通过w2间接呈现原子事实。
- 训练类型明确标记为`atomic + w2 + d2`，最大推理深度仍为2。
- 保留完整程序输入和自主内部计算；d3及以上继续只用于测试。
- 原子样本直接监督最终实体token，不监督END；不输入中间答案，不改成外部程序逐步调用模型。
- 加原子数据改变了此前“没有独立d1训练行”的限制，应明确披露；这些事实本身早已全部出现在w2中。

## 2. 来源数据与接口

使用已有world42，E=500、R=20，20个关系均为500实体上的随机置换。

| 数据类型 | 独特训练记录 | 输入语义 | 输出语义 |
|---|---:|---|---|
| atomic（新增） | 10,000 | `[x,r]` | `f_r(x)` |
| w2（保留来源，渲染待定） | 40,000 | 建议拆成独立的`[x,r]`与`[z,s]` | 各自的单实体答案 |
| d2（保留） | 10,000 | `[x,r,s]` | `f_s(f_r(x))` |
| d3+训练 | 0 | — | — |

原子与d2使用同一紧凑查询语法、同一词表、同一个最终实体预测头，仅关系数量不同。下一版不沿用第五批的TASK包装、稀疏位置格式或独立答案decoder。

所有10,000个`(x,r)`各生成一条原子记录，目标来自已冻结rel_map。示例真实记录：`<e_0> <r_0> → <e_179>`。

本次同步的原子来源数据：

- [train_atomic.json](../data/atomic_joint_2026-09-19/train_atomic.json)
- [来源及校验manifest](../data/atomic_joint_2026-09-19/manifest.json)

记录格式为`{"kind":"atomic","x":0,"r":0,"y":179}`；`y`是监督标签，严禁送入题目输入。数据是为接入准备的来源表，不表示现有训练器已经支持该schema。

已核验：10,000个键全部唯一；恰好覆盖原w2中全部事实；与rel_map一致；每个关系是置换；没有新增深训练题或事实世界。

定义N=ER=10,000，则候选数据池为6N条记录，其中atomic为N，w2为4N，d2为N。数据池大小与训练抽样配比须分别记录，不按60k行简单串接后就宣称已控制曝光。

## 3. 历史提议：4-slot模型下的最小联合训练配比

为单独观察增加原子单任务接口的效果，首个对照暂不同时修改k1关系图、模型结构或推理预算。多伙伴关系图是另一个独立因素。

沿用250k updates、batch256，原子数据从第一阶段就出现，并在d2阶段持续混合：

| 阶段 | updates | 原配方对照：atomic / w2 / d2 | 加原子组：atomic / w2 / d2 |
|---|---:|---|---|
| 一步知识阶段 | 50k | 0 / 256 / 0 | 128 / 128 / 0 |
| 两步联合阶段 | 200k | 0 / 128 / 128 | 64 / 64 / 128 |

保持各来源自己的固定数据池，组内均匀采样。d2样本流、布局规则和循环预算流使用独立RNG，同seed尽可能配对。训练器接入时须记录真实流和来源hash，不仅记录名义配比。

基础loss沿用每packet的`mean(答案实体CE) + END CE`。这一配比保持每步256个实际packet，第二阶段的128个d2曝光不变。

### 不能忽略的曝光差异

把一个双题w2替换成一个原子单题，会减少原始实体标签数；固定256实际packet和固定128个d2时无法同时匹配所有计数。

第二阶段：

- 对照有384个实体目标token，加原子组有320个。
- w2/atomic部分的直接原子事实出现次数为256对192。
- 每packet实体CE先取平均，所以两臂的实体loss总权重均为256，END总权重均为256；直接原子答案的加权loss总量均为128。

按整个建议日程，加原子组累计呈现19.2M atomic、19.2M w2、25.6M d2，共64M记录；原子单题必须持续训练，不能只预热后撤掉。原子事实的原始与加权曝光应分别统计。

若需要严格匹配原子事实曝光，可以增加一个独立对照：第二阶段仍选128个w2来源，其中64个保持完整，另64个各拆成两个单任务原子packet；两个原子loss各乘1/2，再与128个d2按原256个来源单位平均。此时实际为128 atomic +64 w2 +128 d2=320个packet。它匹配语义事实曝光和加权监督，但不匹配实际packet数与计算量，应单列而不混称同预算。

## 4. 读数与解释

必要读数：全10k原子事实在单TASK接口的准确率与格式错误、较大w2新配对集合、未见关系对d2、d3+。所有checkpoint选择仍只用浅验证，深题不进入训练或选点。

- 原子接口恢复、d2仍失败：固定伙伴依赖或组合机制仍未解决。
- 原子与未见d2都改善：支持独立原子接口监督有帮助；是否有深泛化需另测。
- d2改善但d3仍失败：明确区分“学会两步重组”和“学会继续递归执行”。

原子训练成功不保证d2成功，更不保证任意深度。没有理由预先取消组合留出和深度测试。

## 5. 论文数据的准确对应

《Loop, Think, & Generalize》v2使用人工生成的符号KG，而非自然语言语料，也不采用我们的w2双任务格式。

1. **§5两跳系统性泛化**：E=2000、R=200、每实体平均20条出边，因此40k原子事实（不是400k）。40k原子全部训练，其中38k CID事实允许进入273.6k两跳组合训练，2k COOD事实只作原子训练。ID测试3k新两跳题；OOD测试近2k由COOD事实组成的两跳题。OOD中的原子知识不是未见知识，而是此前没有被用于组合的知识。
2. **§6深度外推**：E=200、R=10，每关系为随机置换，2k原子全覆盖。当前公开`getNhopfact.py`每深度生成15,750个去重程序，再分15,000训练和750测试；2至40跳预生成并不表示全部马上加入训练，实际按95%门槛逐深度课程引入。`create_dataset.py`组合这些来源，原子事实持续保留。
3. **语义格式**：原子`<e_x><r_a> → <e_y>`，两跳`<e_x><r_a><r_b> → <e_z>`。中间实体不在输入里。公开数据文件的target_text可能含输入前缀和结束标记，而训练collator选择最后实体作监督；不要把文件字段的完整字符串误读成CoT目标。
